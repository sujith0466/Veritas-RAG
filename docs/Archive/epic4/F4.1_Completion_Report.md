## 1. Executive Summary

F4.1 provides secure, end-to-end workspace invitation lifecycle management, allowing workspace owners and administrators to invite users by email with role-based access control, cryptographic token generation and SHA-256 storage, configurable TTL policies, rate-limiting guards against abuse, row-level locking for atomic state transitions, background token expiration sweeps, domain event dispatching, and audit logging.

### 2.2 Data Access Layer
- **Repository:** [`WorkspaceInvitationRepository`](file:///d:/RAGuard/backend/repositories/workspace_invitation.py)
  - Provides pessimistic concurrency control via `SELECT ... FOR UPDATE` row-level locks on atomic status transitions (`get_by_id_for_update`, `get_by_token_hash_for_update`).
  - Filtered queries for active invitations, duplicate checks, workspace-scoped listings, and bulk batch expiration sweeps.

### 2.3 Business Logic & Service Layer
- **Service:** [`WorkspaceInvitationService`](file:///d:/RAGuard/backend/services/workspace/invitation_service.py)
  - **Cryptographic Tokens:** 32-byte URL-safe base64 tokens with 256-bit entropy (`secrets.token_urlsafe(32)`) hashed via SHA-256 (`token_hash`) prior to database persistence. Raw tokens are transmitted exclusively once via email.
  - **Atomic Transactions:** DB commit strictly precedes email dispatch. Email transport failure logs a critical warning without rolling back the invitation record.
  - **Configurable TTL:** Resolves workspace-level TTL from `WorkspaceSettings` (clamped between 1 and 30 days, platform default 7 days).
  - **Rate Limiting:** Multi-tiered sliding window rate limiting:
    - 5 invitations/hour per (workspace, email)
    - 50 invitations/hour per workspace
    - 20 invitations/hour per actor
    - 60-second cooldown on re-sends
  - **Role Hierarchy Enforcement:** Only active `OWNER` or `ADMIN` members may invite, and target role cannot exceed the actor's role privilege.
  - **Enumeration Protection:** Generic status codes and obfuscated failure responses where required.
- **Worker:** [`WorkspaceInvitationExpirationWorker`](file:///d:/RAGuard/backend/services/workspace/invitation_expiration_worker.py)
  - Scheduled background worker that transitions expired `PENDING` invitations to `EXPIRED` in batches of 100, publishing `WORKSPACE_INVITATION_EXPIRED` domain events and writing audit records.

## 4. Architectural Invariants Preserved
- Database commit precedes email dispatch to guarantee data integrity under SMTP failures.
- Raw cryptographic tokens are never stored in the database (only SHA-256 hashes are persisted).
- Row-level locking (`SELECT ... FOR UPDATE`) prevents race conditions during status transitions.
- Enumeration protection prevents scanning and harvesting of email addresses.
- Rate limits guard against email flooding and workspace spam.
