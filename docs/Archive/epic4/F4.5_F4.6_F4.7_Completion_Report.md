# F4.5, F4.6, F4.7 Implementation Completion Report

## 1. Features Implemented

### **F4.5 — Role Assignment / Reassignment**
- Implemented `update_member_role` in `WorkspaceMembershipService` to handle RBAC validations for role upgrades/downgrades (e.g., ensuring at least one owner remains).
- Included security mechanisms to prohibit self-downgrade and restrict actions based on the actor's role.
- Integrated optimistic locking using the `version` field in `WorkspaceMember`.
- Emits `WorkspaceMemberRoleUpdatedEvent`.
- **Cross-cutting Session Invalidation:** Extended `JWTService` with `revoke_user_workspace_tokens()` to implement an `invalid_before` mechanism in Redis, forcing sessions with old roles to instantly expire.

### **F4.6 — Member Removal**
- Implemented `remove_member` in `WorkspaceMembershipService`.
- Prevents removal of the last workspace owner.
- Exposed a self-leave flow (`POST /api/v1/workspaces/{id}/members/leave`) mapping to `remove_member` with `is_self_removal` validation.
- Emits `WorkspaceMemberRemovedEvent`.
- Triggers the same Redis-based token revocation so that removed members lose API access to the workspace immediately without requiring a full re-login.

### **F4.7 — User Profile Management**
- Updated the `User` domain entity to include localization and UI preferences (`display_name`, `timezone`, `language`, `theme_preference`) and optimistic locking (`version`).
- Generated and applied Alembic database migration (`20260802_2e2423fb5e1b_add_f4_7_user_profile_fields`).
- Built `UserProfileService` in `backend/services/user/profile_service.py` to handle profile updates with collision detection (`UsernameTakenError`).
- Replaced the `/users/me/profile` endpoints in `backend/api/v1/routes/users.py` to leverage `UserProfileService` and strictly validate `If-Match` ETags.
- Emits `UserProfileUpdatedEvent`.

## 3. Deviations from Architecture
- For backward compatibility with the existing router structures, the `UserProfileService` integration was applied directly within the existing `backend/api/v1/routes/users.py` instead of creating an entirely new nested router structure. This maintained compatibility for existing frontend clients reliant on the `/api/v1/users/me` namespace.
- Session invalidation was implemented gracefully using an `invalid_before` timestamp stored in Redis (`auth:user:{user_id}:workspace:{workspace_id}:invalid_before`) evaluated directly inside the JWT Middleware upon `verify_token()`. This allowed instantaneous cross-session role revocation without having to keep a mapped registry of JTI strings.
