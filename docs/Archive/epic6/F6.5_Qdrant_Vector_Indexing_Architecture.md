# F6.5 — Qdrant Vector Indexing Architecture

**Feature:** F6.5 — Qdrant Vector Indexing (Namespaced by workspace_id)  
**Epic:** Epic 6 — Knowledge Processing Pipeline  
**ADR References:** ADR-004, ADR-M3-001, ADR-M3-002  
**Architect:** Principal Engineering Review  
**Date:** 2026-08-04  
**Status:** ARCHITECTURE APPROVED — AWAITING IMPLEMENTATION

## 1. Executive Summary

F6.5 establishes the **Qdrant Vector Indexing Worker** as the fifth and final stage of the document ingestion pipeline. It consumes `ChunkEmbedding` records staged in PostgreSQL by F6.4 and synchronizes them as searchable vector points into Qdrant, namespaced strictly by `tenant_id`.

The foundation **already exists** in `backend/modules/vector/`. This document specifies the complete production-grade indexing design — covering collection topology, workspace namespacing, payload schema, idempotency, version/archive lifecycle management, distributed locking, batch upsert, retry handling, consistency verification, collection health checks, and all enterprise observability requirements.

## 4. Collection Strategy & Workspace Namespacing

### 4.1 Collection Naming Convention

```
raguard_knowledge_{dimension}
```

Examples:
- `raguard_knowledge_1536` — OpenAI text-embedding-3-large (1536-dim)
- `raguard_knowledge_1024` — Cohere / Local BAAI (1024-dim)

**Rationale:** Collections are shared across workspaces (tenants) within the same Qdrant cluster. Multi-tenant isolation is enforced **entirely via payload filtering**, not via separate collections per tenant. This is consistent with the existing `QdrantVectorDBProvider.ensure_collection()` implementation.

### 4.2 Workspace Isolation via Payload

Every vector point carries `tenant_id` as a mandatory indexed payload field:

```json
{
  "tenant_id": "org_acme_workspace_a",
  "document_id": "uuid",
  ...
}
```

The `tenant_id` field is **always required** in the `VectorPointDTO` payload validator:

```python
@field_validator("payload")
@classmethod
def validate_mandatory_payload_keys(cls, v):
    required_keys = {"tenant_id", "document_id", "document_version_id", "content_hash"}
    # Already implemented in schemas/payload.py
```

All Qdrant searches **must** include `{"tenant_id": tenant_id}` in filter conditions — this is enforced by the `search_points()` signature contract.

### 4.3 Collection per Dimension

The system maintains **one collection per embedding dimension**:

```python
collection_name = settings.qdrant.collection_name(tenant_id)
# Returns: f"raguard_knowledge_{dimension}"
# NOT f"raguard_{tenant_id}_{dimension}" — shared collection, isolated by payload
```

This avoids collection explosion at scale (thousands of workspaces = thousands of Qdrant collections).

## 5. End-to-End Indexing Flow

### 5.1 Trigger Mechanism

```
EMBEDDING_COMPLETED event
  → Pipeline Event Listener (tasks/listeners.py)
    → sync_vectors_to_qdrant_task.delay(
        document_id, document_version_id, tenant_id
      )
```

### 5.2 Celery Task Execution

```
sync_vectors_to_qdrant_task (queue="ingestion", max_retries=5, acks_late=True)
  → asyncio.run(_async_sync_vectors_task())
    → AsyncSession factory
      → acquire_lock(f"vector:sync:{document_version_id}", timeout=300)
        → VectorStorageService.sync_document_vectors()
```

### 5.3 VectorStorageService.sync_document_vectors() — Detailed Flow

```
1. LOAD EMBEDDINGS
   ChunkEmbedding[] WHERE tenant_id=tenant_id AND document_version_id=ver_uuid AND NOT deleted

2. GUARD: No embeddings found → log warning, return 0 (skip gracefully)

3. ARCHIVE AWARENESS CHECK
   Document.status == "ARCHIVED" → return 0 without indexing
   (Archived documents must not be searchable)

4. LOAD CHUNKS (for rich payload metadata)
   DocumentChunk[] WHERE tenant_id AND document_version_id → chunks_map[chunk_id]

5. DETERMINE COLLECTION
   dimension = embeddings[0].dimension
   target_col = settings.qdrant.collection_name(tenant_id)  # "raguard_knowledge_{dim}"

6. GET OR CREATE VectorIndexMetadata
   repository.get_or_create_metadata(tenant_id, document_id, ver_id, target_col)
   → UNIQUE(tenant_id, document_version_id, collection_name) prevents duplicates

7. IDEMPOTENCY CHECK
   IF metadata.status == "COMPLETED":
     → Log: "Already indexed, skipping" (idempotent re-trigger guard)
     → Return metadata.points_count (no re-upsert)

8. UPDATE SYNC STATUS → PROCESSING

9. ENSURE COLLECTION EXISTS
   provider.ensure_collection(CollectionConfigDTO(
     collection_name=target_col,
     dimension=dimension,
     distance_metric="Cosine",
     on_disk_payload=True,
     scalar_quantization=True  # INT8 ADR-M3-002
   ))

10. CREATE PAYLOAD INDEXES (idempotent — provider handles "already exists")
    indexed_fields = [
      "tenant_id",
      "document_id",
      "document_version_id",
      "content_hash",
      "strategy_used",
      "chunk_index",       # For ordered retrieval
      "model_name",        # For provider-specific filtering
    ]

11. BUILD VECTOR POINTS
    FOR each ChunkEmbedding:
      chunk = chunks_map[emb.chunk_id]
      payload = build_enriched_payload(emb, chunk, doc, tenant_id)
      point = VectorPointDTO(
        point_id=str(emb.chunk_id),  # Deterministic: chunk_id is the point ID
        vector=emb.embedding_vector,
        payload=payload
      )

12. BATCH UPSERT (configurable batch_size, default 500 points)
    FOR each batch of points:
      upserted = await provider.upsert_points(target_col, batch, wait=True)
      QdrantMetrics.record_upsert(latency_ms)

13. PAYLOAD VALIDATION BEFORE UPSERT
    Each VectorPointDTO validated by Pydantic (mandatory keys enforced)
    On InvalidPayloadSchemaError → FATAL, no retry

14. UPDATE SYNC STATUS → COMPLETED (points_count = upserted_count)

15. DISPATCH VECTORS_INDEXED event

16. CLEANUP OLD VERSION VECTORS
    cleanup_old_versions_vectors(document_id, current_version_id, tenant_id)

17. CONSISTENCY VERIFICATION
    Post-upsert count check:
      provider.get_collection_info(target_col)
      Verify points_count delta matches upserted_count (within tolerance)
```

## 6. Payload Schema

### 6.1 Canonical Vector Point Payload

```python
{
    # ── Mandatory Isolation Fields (Indexed) ─────────────────────
    "tenant_id":              str,   # Workspace namespace (KEYWORD index)
    "document_id":            str,   # Parent document UUID (KEYWORD index)
    "document_version_id":    str,   # Source version UUID (KEYWORD index)
    "content_hash":           str,   # SHA-256 of chunk content (KEYWORD index)
    
    # ── Content Fields ────────────────────────────────────────────
    "content":                str,   # Raw chunk text (for search result display)
    "chunk_index":            int,   # Position in document (INTEGER index)
    "token_count":            int,   # Token budget tracking
    "character_count":        int,   # Content size
    
    # ── Structural Fields ─────────────────────────────────────────
    "section_path":           list[str] | None,  # Markdown breadcrumbs
    "page_numbers":           list[int] | None,  # PDF page references
    "strategy_used":          str,   # Chunking strategy (KEYWORD index)
    
    # ── Provider Tracking ─────────────────────────────────────────
    "provider":               str,   # "openai" | "cohere" | "local"
    "model_name":             str,   # "text-embedding-3-large"
    
    # ── User Metadata ─────────────────────────────────────────────
    **user_meta,              # Dynamic K-V tags from Document.user_metadata
}
```

### 6.2 Indexed Fields Summary

| Field | Index Type | Purpose |
|---|---|---|
| `tenant_id` | KEYWORD | Workspace isolation (required on every search) |
| `document_id` | KEYWORD | Document-level filtering and deletion |
| `document_version_id` | KEYWORD | Version-level cleanup |
| `content_hash` | KEYWORD | Deduplication verification |
| `strategy_used` | KEYWORD | Strategy-specific retrieval |
| `chunk_index` | INTEGER | Ordered context window assembly |
| `model_name` | KEYWORD | Provider-specific routing (future multi-provider search) |

## 7. Idempotent Indexing

F6.5 implements three layers of idempotency:

### 7.1 VectorIndexMetadata Guard

```python
if metadata.status == "COMPLETED" and not force_resync:
    return metadata.points_count
```

Prevents re-indexing on EMBEDDING_COMPLETED event re-delivery (common in event-driven systems).

### 7.2 Qdrant Native Upsert

Qdrant's `upsert` operation is **inherently idempotent** — upserting a point with an existing `point_id` updates the vector and payload without creating duplicates.

```python
# Point ID = chunk_id (deterministic UUID, stable across retries)
point_id = str(emb.chunk_id)
```

### 7.3 Distributed Lock

```python
async with acquire_lock(f"vector:sync:{document_version_id}", timeout=300):
    # Prevents concurrent sync of the same document version
```

## 8. Batch Indexing Strategy

### 8.1 Batch Size Configuration

```python
VECTOR_UPSERT_BATCH_SIZE = 500  # points per Qdrant API call
```

For large documents (e.g., 10,000 chunks), the upsert is split into sub-batches:

```python
for i in range(0, len(points), VECTOR_UPSERT_BATCH_SIZE):
    batch = points[i:i + VECTOR_UPSERT_BATCH_SIZE]
    await provider.upsert_points(target_col, batch, wait=True)
```

`wait=True` ensures Qdrant confirms the write before the next batch starts — critical for consistency verification.

### 8.2 Memory Safety

Large document upserts are **streamed in batches** rather than loading all points into memory simultaneously. This prevents OOM issues for documents with thousands of chunks.

## 9. Retry Handling

| Error | Severity | Strategy |
|---|---|---|
| `QdrantConnectionError` (VEC_003) | RECOVERABLE | Exponential backoff: `2^n * 5s`, max_retries=5 |
| `QdrantIndexingTimeout` (VEC_005) | RECOVERABLE | Exponential backoff, max_retries=5 |
| `CollectionNotFoundError` (VEC_001) | RECOVERABLE | Retry after collection creation (auto-heals) |
| `DimensionMismatchError` (VEC_002) | FATAL | No retry — config bug, DLQ immediately |
| `InvalidPayloadSchemaError` (VEC_004) | FATAL | No retry — data bug, DLQ + alert |
| Redis failure (lock acquisition) | RECOVERABLE | Retry after 30s |

**Retry storm prevention:** Jittered exponential backoff (already in `tasks.py`):
```python
countdown = int(2 ** self.request.retries * 5)
```

## 10. Delete Strategy

### 10.1 Document Deletion

On `DOCUMENT_DELETED` or `DOCUMENT_ARCHIVED`:
```python
await service.delete_document_points(document_id, tenant_id)
```

This calls `provider.delete_points_by_filter(col, {"tenant_id": tenant_id, "document_id": str(doc_id)})` across all collections the document was indexed in.

### 10.2 Version Cleanup (Superseded Versions)

On new version indexed:
```python
await service.cleanup_old_versions_vectors(doc_id, new_version_id, tenant_id)
```

Deletes points with filter `{"tenant_id": t, "document_version_id": str(old_version_id)}` from each old version's collection.

### 10.3 Bulk Workspace Deletion

On `WORKSPACE_HARD_DELETED`:
```python
# Delete all points for all documents in this workspace
provider.delete_points_by_filter(col, {"tenant_id": tenant_id})
# Soft-delete all VectorIndexMetadata records for tenant
```

## 11. Update Strategy

### 11.1 Metadata-Only Update

When `Document.user_metadata` changes (F5.7 Metadata Management):
```python
await service.sync_metadata(doc)
```

This re-upserts existing points with updated payload (vectors unchanged). Qdrant's upsert operation naturally handles this — vector remains, payload overwrites.

### 11.2 Content Re-index

On new `DocumentVersion` created and embedded:
1. F6.4 embeds new version → new `ChunkEmbedding` records
2. F6.5 indexes new version → new points in Qdrant
3. F6.5 calls `cleanup_old_versions_vectors()` → purges old version points
4. Result: Only latest version is searchable

- Periodic Celery beat task that cross-references `chunk_embeddings` count vs Qdrant point count per tenant per version
- Runs every 6 hours

## 13. Version Awareness

Before indexing:
```python
version = await doc_repo.get_version(document_version_id)
if version.is_superseded_by_newer:
    logger.warning("Skipping indexing of superseded version")
    return 0
```

If the document has been re-versioned since the embedding was generated (race condition), the indexing is skipped. The newer version's embedding task will handle indexing.

---

## 14. Archive Awareness

```python
document = await doc_repo.get_by_id(document_id, tenant_id, session)
if document.status == "ARCHIVED":
    logger.info("Skipping vector indexing for archived document")
    await repo.update_sync_status(metadata.id, status="SKIPPED")
    return 0
```

Archived documents are **not indexed** and their existing vectors are **deleted** on archival via `remove_archived_document_vectors()`.

## 15. Duplicate Protection

| Scenario | Protection |
|---|---|
| Task delivered twice | `VectorIndexMetadata.status == "COMPLETED"` guard + idempotent Qdrant upsert |
| Concurrent workers same version | Distributed lock on `document_version_id` |
| Race between new version and old cleanup | `cleanup_old_versions_vectors()` uses version filter, not document filter |
| Dimension change between versions | New collection resolves; old collection cleaned up separately |

## 17. Performance Optimization

| Optimization | Details |
|---|---|
| **INT8 Scalar Quantization** | 4x memory reduction, ~5% precision loss (acceptable for RAG) |
| **On-disk payload** | `on_disk=True` — payloads stored on disk, not RAM |
| **HNSW Index** | `m=16, ef_construct=100` (Qdrant defaults, optimized for 1536-dim) |
| **Batch upsert size** | 500 points per call (balanced throughput vs latency) |
| **Payload index** | KEYWORD indexes on `tenant_id`, `document_id` for O(1) filter |
| **wait=True** | Synchronous confirmation from Qdrant (consistency over throughput) |
| **gRPC preference** | `QdrantVectorDBProvider` uses `AsyncQdrantClient` with gRPC for reduced latency |

## 20. Multi-Workspace Isolation Summary

| Layer | Mechanism |
|---|---|
| **Qdrant payload** | `tenant_id` mandatory in every point payload (validated by Pydantic) |
| **Search filter** | All `search_points()` calls require `{"tenant_id": ...}` filter |
| **Delete filter** | All `delete_points_by_filter()` include `tenant_id` |
| **PostgreSQL** | All `VectorIndexMetadata` queries include `WHERE tenant_id = :tid` |
| **Distributed lock** | Lock scoped to `document_version_id` (not shared across tenants) |
| **Events** | All events carry `tenant_id` in payload |
| **Metadata** | `UNIQUE(tenant_id, document_version_id, collection_name)` constraint |

## 21. Queue Routing

```
Queue:       "ingestion"   (existing, already configured)
Exchange:    "ingestion"
Routing Key: "ingestion"
max_retries: 5
acks_late:   True
```

The `ingestion` queue handles vector sync tasks alongside F6.2 extraction tasks. For production scaling, a dedicated `indexing` queue may be warranted (architecture allows easy re-routing via `task_routes`).

## 22. Dead Letter Queue

After `max_retries=5` exhausted:
1. `VectorIndexMetadata.status → FAILED`
2. `ProcessingJob.status → FAILED`
3. `ProcessingJob.dlq_reason` = error message
4. `ProcessingJob.dlq_at` = now()
5. `VECTORS_INDEX_FAILED` event dispatched
6. Admin monitoring alert triggered

## 25. Open Design Decisions

| Decision | Recommended Approach |
|---|---|
| Dedicated `indexing` queue | Separate from `ingestion` queue in high-throughput scenarios |
| gRPC vs HTTP for Qdrant | gRPC preferred (already in `AsyncQdrantClient` defaults) |
| Consistency verification tolerance | Allow ±5 points mismatch (Qdrant eventual consistency during indexing window) |
| Multi-vector support | Future: Named vectors for sparse + dense hybrid (Epic 8) |
| Payload encryption | Phase 5: Encrypt `content` field at rest for sensitive workspaces |
