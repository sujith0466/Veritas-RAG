## 2. Implemented Architecture & Module Breakdown

### 2.1 Feature F6.6: ProcessingJob Lifecycle State Machine & Step Observability
*   **Lifecycle State Transitions:** Strict validation of job transitions (`QUEUED` -> `PROCESSING` -> `COMPLETED` / `FAILED` / `DLQ` / `CANCELLED`).
*   **Step Metrics & Tracing:** Each stage (`upload`, `extraction`, `ocr`, `chunking`, `embedding`, `indexing`) records millisecond-precision execution duration and output counts in `step_metrics` JSONB.
*   **Distributed Claim Mutex:** Redis-based distributed locking (`job:claim:{job_id}`) prevents duplicate worker claims and race conditions.
*   **Stale Job Re-queueing Engine:** Identifies orphaned jobs claimed by dead workers past heartbeats and automatically requeues them.

### 2.2 Feature F6.7: Dead Letter Queue (DLQ) & Remediation Engine
*   **Exponential Backoff & Retries:** Automatic retries with jitter up to configurable `max_retries` before quarantine into DLQ.
*   **Audit Logging:** Immutably records every failure step, error code, stack trace, and remediation action.
*   **Granular Step Resumption:** Provides ability to resume execution specifically from the failed step (e.g., resuming from `ocr` or `embedding` without repeating expensive extraction).
*   **Bulk Triage & Dismissal:** Admin API for batch remediation, error filtering, and bulk DLQ dismissal.

### 2.3 Feature F6.8: S3 Event-Driven Ingestion Pipeline
*   **Presigned Direct Uploads:** Generates secure AWS S3 / MinIO presigned PUT URLs with SHA-256 and content-type enforcement.
*   **S3 Event Webhooks:** Handles AWS S3 and SNS/SQS event notifications (`s3:ObjectCreated:*`).
*   **Idempotency & Deduplication:** Redis key deduplication (`s3:event:{bucket}:{object_key}:{etag}`) ensures duplicate event notifications are safely ignored without re-processing.
*   **Strict Entity Mapping:** Fully unified with `Document`, `DocumentVersion`, and `StorageObject` models.
