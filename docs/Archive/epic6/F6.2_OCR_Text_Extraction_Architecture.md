# RAGuard V2: F6.2 — OCR & Text Extraction Worker Architecture

## 1. Executive Summary
F6.2 defines the enterprise-grade OCR and text extraction worker that forms the critical ingestion point for the Knowledge Processing Pipeline in RAGuard V2. Operating strictly within the principles of Domain-Driven Design (DDD) and Command Query Responsibility Segregation (CQRS), this worker transforms raw binary document payloads into clean, normalized, structured text artifacts. 

As the primary active processing stage, the F6.2 worker is orchestrator-driven. It receives asynchronous processing commands via the `ProcessingJob` infrastructure (F6.1) over Celery queues, extracts textual content and associated metadata, and produces normalized text artifacts (`text.txt` and `extraction.json`) stored securely in a tenant-isolated, versioned S3 path structure. The resulting artifacts are strictly deterministic and act as the definitive source material consumed downstream by chunking (F6.3) and embedding processes. 

## 2. Feature Scope
The F6.2 architecture provides comprehensive support for translating varied source materials into unified textual representations. Key deliverables include:
- **Native text extraction**: Comprehensive parsing for PDF, DOCX, PPTX, XLSX, HTML, Markdown, Plain Text, CSV, and RTF formats.
- **Image handling and OCR fallback**: Robust pipeline (Docling → Tesseract → Emergency fallback) triggered automatically via heuristic analysis of text yield or file mime-type (PNG/JPG/TIFF/WEBP).
- **Language detection**: Integration with `langdetect` library for high-confidence language attribution.
- **Unicode normalization**: Multi-stage encoding detection (`chardet`/`charset-normalizer`) and Unicode standardization (NFKC), combined with custom whitespace and line-ending heuristics.
- **Document metadata extraction**: Deep inspection of file properties yielding page count, word count, author, creation date, and titles.
- **Page-level tracking**: Maintaining spatial awareness mapping generated text back to physical or logical source pages.
- **Failure handling and retry strategy**: Fault-tolerant retry mechanisms for transient errors and partial success preservation.
- **Worker orchestration and concurrency**: Resilient Celery task definitions, multi-threading for large page batches, and distributed Redis locking to enforce idempotency.
- **Systems integration**: Seamless updates to `ProcessingJob` state, event emission via `EventDispatcher` (`EVENT_TEXT_EXTRACTED`), comprehensive `DocumentEventLog` tracking for auditability, and storage interactions via `LocalStorageProvider`/S3.

## 3. Extraction Pipeline Architecture

The F6.2 extraction pipeline operates as a sequence of deterministic stages governed by the worker logic. 

### 3.1 High-Level Pipeline Diagram

```text
ProcessingJob → OCRExtractionWorker
  ├─ Stage 1: File Validation & MIME Detection
  ├─ Stage 2: Native Extraction Attempt
  │   ├─ PDF → PDFExtractor (pdfplumber + PyMuPDF fallback)
  │   ├─ DOCX → DOCXExtractor (python-docx)
  │   ├─ PPTX → PPTXExtractor (python-pptx)
  │   ├─ XLSX → XLSXExtractor (openpyxl)
  │   ├─ HTML → HTMLExtractor (BeautifulSoup)
  │   ├─ Markdown → MarkdownExtractor (mistune)
  │   ├─ Images → needs_ocr=True → OCR Pipeline
  │   └─ Plain Text/CSV → TextExtractor
  ├─ Stage 3: OCR Fallback (if needs_ocr or text_yield < threshold)
  │   ├─ Primary: DoclingOCREngine
  │   └─ Secondary: TesseractOCREngine
  ├─ Stage 4: Post-Processing
  │   ├─ Encoding detection & normalization (chardet → NFKC)
  │   ├─ Language detection (langdetect)
  │   ├─ Unicode normalization
  │   ├─ Page-level text assembly
  │   └─ Metadata extraction (page count, word count, title, author)
  ├─ Stage 5: Artifact Persistence
  │   ├─ Normalized text.txt → S3 versioned path
  │   └─ extraction.json metadata → S3 versioned path
  └─ Stage 6: Event Emission
      ├─ EVENT_TEXT_EXTRACTED
      └─ PROCESSING_JOB_STEP_COMPLETED (triggers F6.3 chunking)
```

## 4. Extractor Registry & Format Support

The `ExtractorRegistry` acts as a domain service to route files based on MIME type to specific `BaseExtractor` implementations.

| Format | MIME Type | Extractor Class | Library | OCR Required | Notes |
|--------|-----------|-----------------|---------|--------------|-------|
| **PDF (text)** | `application/pdf` | `PDFExtractor` | `pdfplumber` | No (unless scan) | Yields `needs_ocr=True` if <50 words/page are found. |
| **PDF (scanned)** | `application/pdf` | `PDFExtractor` | `pdfplumber` | Yes | Detected dynamically via heuristic text yield thresholding. |
| **DOCX** | `application/vnd.openxmlformats...` | `DOCXExtractor` | `python-docx` | No | Preserves native heading hierarchy and structural order. |
| **PPTX** | `application/vnd.ms-powerpoint...` | `PPTXExtractor` | `python-pptx` | No | Linearizes text via slide-by-slide extraction. |
| **XLSX** | `application/vnd.ms-excel...` | `XLSXExtractor` | `openpyxl` | No | Flattens grid data using cell linearization. |
| **Images** | `image/*` (PNG/JPG/TIFF/WEBP) | `ImageExtractor` | `Pillow` | Yes (always) | Bypasses native extraction; routes immediately to OCR pipeline. |
| **HTML** | `text/html` | `HTMLExtractor` | `BeautifulSoup` | No | Strips semantic tags while preserving underlying layout structure. |
| **Markdown** | `text/markdown` | `MarkdownExtractor` | `mistune` | No | Preserves heading scopes as positional metadata. |
| **Plain Text** | `text/plain` | `TextExtractor` | built-in | No | Strongly relies on encoding detection before read. |
| **CSV** | `text/csv` | `CSVExtractor` | `csv` stdlib | No | Performs row/column stringification and flattening. |
| **RTF** | `application/rtf` | `RTFExtractor` | `striprtf` | No | Strips formatting tags. |

*Exception Path:* Unsupported MIME types trigger immediate failure throwing `DocumentDomainException(EXTRACT_002, FATAL)`.

## 5. OCR Pipeline (Extended from Existing)

The OCR fallback mechanism builds upon the existing `OCRPipeline` to handle scanned PDFs and native image files robustly.

### 5.1 Extended OCR Engine Chain
1. **Confidence Thresholding**: After executing an engine, the result's confidence score is evaluated. If confidence is below 0.6 (60%), the pipeline escalates to the next available engine.
2. **Language HINT Injection**: Detected language metadata from earlier stages (or workspace defaults) are injected into the OCR engine configuration to prune candidate characters and increase transcription accuracy.
3. **Page-by-Page Parallelism**: Documents exceeding 100 pages are segmented into distinct page batches, distributed across up to 4 local worker threads to minimize latency.
4. **Emergency Fallback**: If all configured engines fail to produce intelligible text, an emergency fallback emits partial strings alongside a critical warning flag rather than outright dropping the processing block.

### 5.2 OCR Engine Comparison
| Engine | Accuracy | Speed | Languages | Use Case |
|--------|----------|-------|-----------|----------|
| **Docling** | High | Medium | 90+ | **Primary:** Complex layouts, mixed text-table scenarios. |
| **Tesseract** | Medium | Fast | 100+ | **Secondary:** Simple flat scans, older artifact rendering. |
| **Emergency** | Low | Fast | ASCII | **Tertiary:** Basic character boundary extraction when primary ML fails. |

### 5.3 OCR Quality Gates
- **Minimum Word Count Gate**: If extraction yields < 5 words total across an entire document (not applicable to short single-page images), set the `extraction_failed` flag.
- **Confidence Gate**: If the best-effort OCR engine (e.g., Tesseract) yields confidence < 40%, flag the output with a `low_quality` attribute in the metadata.
- **Language Coherence Check**: Cross-validate the statistically detected language against the expected language designated at the workspace level.

## 6. Language Detection
- **Technology**: Utilizes `langdetect` (probabilistic n-gram models) in tandem with `charset-normalizer` for accurate byte decoding.
- **Constraints**: Requires a minimum text length of 50 characters to trigger. Shorter texts default to `unknown`.
- **Threshold**: Confidence must exceed 0.85 to authoritatively set `document.language`. If below 0.85, language is marked `unknown`.
- **Multilingual Handling**: Defaults to identifying and persisting the language of the majority text block.
- **Persistence**: Saved to both the aggregate root `Document.language` property and serialized inside `DocumentVersion.metadata_json`.

## 7. Unicode & Encoding Normalization
Transformations occur in a strict sequential filter pattern:
1. **Byte Encoding Detection**: Use `chardet` (fallback `charset-normalizer`) to divine original byte encoding.
2. **String Decoding**: Decode to native Python `str` using `errors='replace'` to handle malformed bytes gracefully without crashing.
3. **Unicode Normalization**: Execute `unicodedata.normalize('NFKC', text)` to enforce a consistent semantic representation (combining characters, ligatures).
4. **Custom Rule Application**: Cleanse null bytes (`\x00`), normalize all line endings to `\n`, and collapse anomalous sequential whitespace/tabs into single spaces (unless structured formatting requires otherwise).
5. **BOM Stripping**: Explicitly strip Byte Order Marks (BOM) left over from UTF-8/UTF-16.
6. **RTL Processing**: Detect Right-to-Left languages (Arabic, Hebrew) and apply bidirectional algorithm (bidi) handling if sequence structure necessitates correction for linear chunking.
7. **Result**: Clean UTF-8 encoded text is sent downstream to the S3 artifact store.

## 8. Page-Level Text Tracking
To facilitate rich downstream citation and contextual grounding:
- Extractor implementations must return typed output: `list[PageText]` where `PageText` comprises `{page_number: int, text: str, word_count: int}`.
- This relational mapping is serialized and stored in the `extraction.json` artifact.
- Top-level `DocumentVersion.metadata_json` aggregates this as `{page_count, pages: [{page_number, word_count}]}`.
- For inherently non-paginated or continuous-scroll formats (HTML, Markdown, Plain Text), the entire content is attributed to `page_number=1`.

## 9. Document Metadata Extraction
The extraction pipeline unearths deep properties stored via the `BaseModel` framework:

| Property | Source | Storage Location |
|----------|--------|------------------|
| **title** | PDF metadata, DOCX props, filename | `metadata_json` |
| **author** | PDF metadata, DOCX properties | `metadata_json` |
| **created_at** | OS file metadata, internal doc props | `metadata_json` |
| **page_count** | Extracted natively from structure | `Document.page_count` |

## 10. Failure Handling & Retry Strategy

### 10.1 Error Classification Table
Errors mapping to specific infrastructure responses:

| Error Code | Severity | Trigger | Action |
|------------|----------|---------|--------|
| **EXTRACT_001** | `RECOVERABLE` | Extractor library runtime crash (OOM, segfault) | Celery retry (up to 2x, exponential backoff) |
| **EXTRACT_002** | `FATAL` | Unsupported MIME type / Format mismatch | DLQ immediately, fail `ProcessingJob` |
| **EXTRACT_003** | `FATAL` | File integrity compromised (corrupted binary) | DLQ immediately, fail `ProcessingJob` |
| **OCR_001** | `RECOVERABLE` | OCR engine sub-process timeout | Fallback to next engine in chain |
| **OCR_002** | `FATAL` | Absolute failure; no text yielded across all engines | DLQ with partial artifact flagged |
| **OCR_003** | `RECOVERABLE` | Output confidence < 40% | Retry via alternative engine strategy |
| **STORE_001** | `RECOVERABLE` | S3 write/network timeout | Celery retry (up to 3x) |
| **STORE_002** | `FATAL` | Source storage object not found | DLQ immediately, fail `ProcessingJob` |

### 10.2 Partial Success Policy
If a fatal error occurs late in extraction but the pipeline has successfully processed at least 10 words, the system will save the partial artifact and append a `low_quality_flag=true` boolean to the metadata. The `ProcessingJob` continues to the F6.3 chunking stage but emits a distinct WARNING event to notify the tenant of degradation.

## 11. Worker Orchestration

### 11.1 Celery Task Definition
- **Target**: `backend.document.workers.extraction.process_extraction_task`
- **Routing**: Routed to the `ingestion` named queue, honoring priority values derived from F6.1 queue topology.
- **Configuration**: Uses `bind=True`, `acks_late=True` (to prevent message loss on worker segfault), `task_reject_on_worker_lost=True`, and `max_retries=5` utilizing `self.retry(exc=..., countdown=...)` for exponential backoff.
- **Execution**: Invoked within an `asyncio.run()` context for IO-bound concurrency where applicable.

### 11.2 Worker Flow
1. **Locking**: Acquire `Redlock` distributed lock: `raguard:{tenant_id}:job:{job_id}:lock`.
2. **Idempotency Check**: Verify `ProcessingJob.status` to skip processing if already in `PROCESSED` or `CHUNKING` state.
3. **State Transition**: Advance `ProcessingJob` status (`CLAIMED` → `RUNNING`), set step `extraction_started`.
4. **Execution**: Perform the multi-stage pipeline (Validation → Extract → OCR → Normalize → Persist).
5. **Telemetry**: Write step transition metrics directly to the `ProcessingJobStep` CQRS model.
6. **Events**: Publish domain events to the in-process `EventDispatcher` (with Celery handling cross-process routing).
7. **Success**: Transition `Document` to `PROCESSED`, step to `EXTRACTION_COMPLETED`, and autonomously enqueue the downstream F6.3 chunking task.
8. **Failure**: Catch `DocumentDomainException`, execute error classification logic, apply retry or route to Dead Letter Queue (DLQ).
9. **Cleanup**: Guarantee Redis lock release in the outermost `finally` block.

### 11.3 Memory Management
- **Streaming**: Always utilize `BinaryIO` file streams from the storage provider; strictly forbid loading entire files into memory matrices.
- **Generators**: PDF extraction must yield `PageText` sequentially. Large PDFs (>100MB) are processed in buffered subsets.
- **Garbage Collection**: Apply explicit `del` to dense memory constructs (image tensors, layout caches) post-stage.
- **Circuit Breaker**: Hard file limit of 500MB (configurable per tenant). Excess files result in `EXTRACT_004` (FATAL) and bypass extraction entirely.

## 12. Integration Points

### 12.1 Integration with F6.1 (ProcessingJob)
- The Celery worker signature extracts `job_id`.
- The aggregate root `ProcessingJob` is hydrated to resolve `document_id`, `version_id`, and `tenant_id`.
- Mutates `ProcessingJob` state by calling `ProcessingJobService.update_step()`, closing via `.complete_job()` or `.fail_job()`.

### 12.2 Integration with Storage Layer
- Retrieves the raw binary source via `storage.get_stream(version.storage_object.object_key)`.
- Persists the normalized UTF-8 string to `get_versioned_path(tenant_id, doc_id, version, 'normalized', 'text.txt')`.
- Persists metadata to `get_versioned_path(tenant_id, doc_id, version, 'metadata', 'extraction.json')`.
- Upon success, the domain service updates `DocumentVersion.extracted_text_path`.

### 12.3 Integration with Document Lifecycle
- Sequentially mutates `Document.status`: `EXTRACTING` → `OCR` (conditional) → `MANIFEST_GENERATING` → `PROCESSED`.
- Updates statistical counts (`Document.word_count`, `Document.page_count`, `Document.language`).
- Enforces CQRS principles by writing immutable state change records to `DocumentEventLog`.

### 12.4 Event Emission
The `EventDispatcher` routes the following `BaseEvent` implementations (`EventType` enum):
- `EVENT_METADATA_EXTRACTED`
- `EVENT_TEXT_EXTRACTED`
- `EVENT_OCR_COMPLETED` (conditional)
- `PROCESSING_JOB_STEP_COMPLETED` (which directly serves as the invocation trigger for chunking via Celery)

## 13. Multi-Tenant Isolation
- The `tenant_id` is passed downward as an immutable context property to all repository queries, ensuring RLS (Row-Level Security) isolation at the Postgres layer.
- `get_versioned_path()` strictly namespaces S3 artifact keys via `tenant_id` prefixes.
- `DocumentEventLog` entries mandate `tenant_id` for segregated compliance auditing.
- Redis concurrency locks (`Redlock`) incorporate `tenant_id` in the URI schema to prevent cross-tenant key collision.
- Workers possess zero visibility into cross-tenant document collections.

## 14. Security
- **Content Scanning**: Architecture supports an optional pre-hook routing streams to a ClamAV daemon for malware detection (tenant-configurable).
- **Size Constraints**: File sizes are pre-validated via metadata before bytestreams are initialized, preventing algorithmic complexity attacks.
- **Path Traversal Prevention**: S3 artifact paths strictly enforce tenant bounds; relative paths provided via manifest manipulation are aggressively sanitized.
- **Log Masking**: Python `logging` strictly forbidden from outputting PII. Worker logs emit `document_id` and `job_id` exclusively, never textual context.
- **Cache Volatility**: Raw OCR results and intermediate text extraction nodes are never persisted in Redis to prevent lingering unencrypted artifacts in memory cache.

## 15. Performance at Scale
- **Streaming Handlers**: The extraction worker architecture leverages streaming I/O to maintain O(1) memory complexity relative to file size.
- **Parallel OCR**: Large scanned targets invoke up to 4 parallel processing threads per worker execution context for batched page OCR transcription.
- **Multipart Uploads**: S3 artifacts exceeding chunk thresholds default to multipart upload behavior via the abstraction layer.
- **Deduplication**: SHA-256 `content_hash` evaluations occur at the ingress boundary; matching hashes against known valid extracted versions bypass the entire F6.2 pipeline.
- **SLAs**: Targeted infrastructure yields > 1,000 documents per hour across a 4-worker instance pool, maintaining a P99 extraction latency < 30 seconds for standard commercial documents.

## 17. Disaster Recovery
- **Artifact Immutability**: All normalized text and metadata payloads leverage native S3 object versioning; overrides are prevented.
- **Pipeline Idempotency**: Because Celery `acks_late=True` is enforced, terminating a worker instance mid-flight will simply cause the `ProcessingJob` to re-enter the queue without duplicate state mutation.
- **State Recovery**: If `text.txt` exists securely in S3 but Postgres transaction committal failed (network partition), the F6.2 worker gracefully acknowledges the existing S3 artifact hash and fast-forwards pipeline state to `PROCESSED`.
- **DLQ Retention**: Messages failing absolute max-retries are parked in a robust PostgreSQL-backed DLQ indefinitely, permitting manual operator review and re-driving after parser logic updates.
