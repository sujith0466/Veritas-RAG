# F5.7 & F5.8 Implementation Plan

## Phase 1 — Database & Migrations
- **Required schema changes**:
  - Add `user_metadata` (JSONB) to `documents` table.
  - Create `bulk_batches` table with columns: `id`, `tenant_id`, `created_by`, `status`, `total_jobs`, `created_at`, `updated_at`.
- **Indexes**:
  - GIN index on `documents.user_metadata` using `jsonb_path_ops`.
  - B-Tree index on `bulk_batches.tenant_id` and `bulk_batches.status`.
- **Constraints**:
  - `user_metadata` default to empty JSON object `{}`.
  - `bulk_batches` tenant foreign key constraint.
- **Rollback considerations**:
  - Ensure down-migration drops the `bulk_batches` table and `user_metadata` column cleanly.
- **Files to create**: `backend/alembic/versions/xxxx_add_f57_f58_schemas.py`
- **Files to modify**: None
- **Dependencies**: Alembic, PostgreSQL
- **Risks**: GIN index creation on large `documents` table might lock table (needs `CONCURRENTLY` if live, but standard creation is fine for dev/standard).
- **Validation checkpoint**: Run `alembic upgrade head` and `alembic downgrade -1` to verify reversibility.

## Phase 3 — Repository Layer
- **CRUD operations**:
  - `DocumentRepository`: Add methods for `update_metadata`, `remove_metadata_key`.
  - `BulkBatchRepository`: `create_batch`, `get_batch`, `update_batch_status`.
- **Query optimizations**:
  - Utilize PostgreSQL JSONB operators (`@>`, `?`) in `DocumentRepository.search_by_metadata`.
- **Transaction boundaries**:
  - Metadata updates utilize `SELECT ... FOR UPDATE` row-level locks to prevent concurrent JSONB modification loss.
- **Files to create**: `backend/document/repositories/bulk_batch_repository.py`
- **Files to modify**: `backend/document/repositories/document_repository.py`
- **Dependencies**: SQLAlchemy AsyncSession
- **Risks**: Deadlocks during concurrent metadata updates if sorting is not enforced.
- **Validation checkpoint**: Unit tests for repository methods verifying SQL generation.

## Phase 4 — Service Layer
### F5.7
- **Metadata CRUD**: Implement service methods to validate and apply full overwrites or partial patches.
- **Validation**: Validate max keys (100), max lengths, and reject system reserved keys (`__*`).
- **Redis locking**: Wrap updates in `acquire_lock(f"ws:{tenant_id}:doc:{document_id}")`.
- **Event publishing**: Emit `EVENT_DOCUMENT_METADATA_UPDATED`.
- **Vector metadata synchronization**: Queue Celery task to sync new metadata into Qdrant.

### F5.8
- **Bulk batch creation**: Initialize batch, generate S3 presigned POST URLs for all files.
- **Presigned URL generation**: Enforce 15-minute expiry and strict `content-length-range`.
- **Batch orchestration**: Track batch completion.
- **Progress aggregation**: Use Redis `INCR batch_progress:{id}` for atomic progress counting.
- **Retry handling**: Handle DLQ routing.
- **Cancellation**: Redis flags for cancellation logic (`bulk_cancel:{batch_id}`).
- **DLQ replay**: Expose logic to replay failed jobs.

- **Files to create**: 
  - `backend/document/services/bulk_upload_service.py`
  - `backend/document/services/metadata_service.py` (or extend DocumentService)
- **Files to modify**: `backend/document/services/document_service.py`
- **Dependencies**: Redis, Boto3 (S3)
- **Risks**: Presigned URL misconfiguration leading to upload failures.
- **Validation checkpoint**: Service layer mock tests passing.

## Phase 5 — Background Workers
- **Celery tasks**:
  - `sync_document_metadata_to_vectors_job`: Updates Qdrant points with new user metadata payload.
  - `dispatch_bulk_upload_job`: Process bulk uploaded files from S3, run AV, extraction, embedding.
- **Queue routing**:
  - Route metadata sync to `vector_ops` queue.
  - Route bulk upload processing to `ingestion_default` or `ingestion_high_priority`.
- **Retry strategy**: Exponential backoff, `acks_late=True`.
- **Failure recovery**: Dead Letter Queue routing upon exceeding max retries.
- **Idempotency**: All vector and DB operations check state before mutating.

- **Files to create**:
  - `backend/document/workers/metadata_sync.py`
  - `backend/document/workers/bulk_upload.py`
- **Files to modify**: None
- **Dependencies**: Celery, Qdrant Client
- **Risks**: Inconsistent Qdrant state if sync task fails completely.
- **Validation checkpoint**: Celery task unit tests pass.
