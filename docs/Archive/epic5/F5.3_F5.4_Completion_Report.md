# RAGuard V2 — F5.3 & F5.4 Completion Report

## 1. Executive Summary

This report certifies the successful implementation of Epic 5 (Folders) Phase 2 features:
- **F5.3: Folder Move (Reparenting)**
- **F5.4: Folder Hard Delete (Permanent Pruning Background Task)**

The implementation adheres strictly to the approved enterprise architecture blueprints. All components across the Database, Domain, Service, Celery Workers, and API layers have been integrated with robust concurrency controls (Redis Locks, `FOR UPDATE` skips) and comprehensive unit and integration testing.

## 2. Completed Scope

### 2.1 Database & Migrations
- `Folder` table extended with `purge_status`, `purge_at`, `purge_started_at`, and `purge_worker_task_id` columns.
- Applied optimized GIN/B-Tree indices for background job polling (`ix_folders_purge_scheduled`).
- Alembic migration generated and successfully applied across the database.

### 2.2 Domain & Audit Logs
- Registered 6 new domain events in `backend.core.events.types` (e.g., `FOLDER_MOVED`, `FOLDER_SUBTREE_MOVED`, `FOLDER_HARD_DELETED`).
- Added robust system audit logging for reparenting and permanent deletion tracking.

### 2.3 Repository Layer
- Enhanced `FolderRepository` with:
  - `get_folder_with_lock`: Deterministic row-level locking.
  - `check_cycle`: Prevents recursive hierarchy cycles during reparenting.
  - `get_subtree_height`: Dynamically calculates depth to enforce the hard 10-level limit.
  - `get_eligible_for_purge`: SKIP LOCKED polling for retention celery workers.

### 2.4 Service Layer
- **Folder Move**: Added `FolderService.move_folder`. Implemented ordered dual-locking to prevent distributed deadlocks, optimized optimistic concurrency version bumping, and emitted domain events triggering background cascade jobs.
- **Hard Delete (Purging)**: Added `FolderService.early_hard_delete_folder` allowing Workspace Admins to bypass the 30-day soft-delete grace period. 

### 2.5 Background Workers (Celery)
- **Cascade Move**: `cascade_move_subtree` worker added to the `folders.critical` queue. Recursively updates paths and depth counters for descendants after a move.
- **Purging Framework**: `hard_delete_folder_subtree` worker added to `folders.purge`. Follows a distributed locking model to securely erase corresponding documents, embeddings, S3 objects, and Database rows.
- **Retention Cron**: `FolderRetentionWorker` configured via Celery Beat to execute every 6 hours and transition expired soft-deleted folders to hard-delete phase.

### 2.6 API Layer
- `POST /workspaces/{workspace_id}/folders/{folder_id}/move`: Invokes reparenting.
- `DELETE /workspaces/{workspace_id}/folders/{folder_id}/hard-delete`: Admin override for immediate erasure.
- `GET /workspaces/{workspace_id}/folders/{folder_id}/purge-status`: Polling endpoint for permanent deletion ETA.

### 2.7 Frontend
- Integrated TS wrappers (`folderService.ts`, `folderStore.ts`) to seamlessly surface backend move and purge workflows to React components.
- Upgraded the type definitions (`Folder`, `FolderPurgeStatus`).
- Verified production build compatibility.
