## 3. Repository Layer

### Repository Updates (`backend/repositories/folder_repository.py`)
- No new repositories are strictly needed, but `FolderRepository` will require several new methods:
  - `get_folder_with_lock`: `SELECT FOR UPDATE SKIP LOCKED` for Phase 1 Move transaction.
  - `check_cycle`: Execute the path prefix `LIKE` query to detect move cycles.
  - `get_subtree_height`: Execute the recursive CTE to compute the max depth of a subtree.
  - `get_eligible_for_purge`: Query folders where `purge_at <= NOW()` and `purge_status IS NULL`.
- **Transaction Boundaries:** Handled primarily by the service layer via SQLAlchemy `session.commit()`.

## 4. Service Layer

### Service Updates (`backend/services/folder_service.py` & new modules)
- Update `FolderService` (or create `FolderMoveService` & `FolderHardDeleteService` for separation of concerns):
  - **Move Logic (Phase 1):**
    - `move_folder(workspace_id, folder_id, new_parent_id, expected_version, actor_id)`
    - Validations: Soft-delete checks, Cycle detection, Depth constraint, Name uniqueness.
    - Locks: Consistent ordering lock on `folder_id` and `new_parent_id`.
    - DB Updates: Parent, Path, Depth, Version, `cascade_status='move_pending'`.
    - Event: Publish `FOLDER_MOVED`.
    - Trigger Celery Task.
  - **Soft Delete Modification (F5.4 linkage):**
    - When `soft_delete_folder` is called, automatically set `purge_at = deleted_at + 30 days` and `purge_status = 'scheduled'`.
  - **Hard Delete Logic (Admin Trigger):**
    - `early_hard_delete_folder(workspace_id, folder_id, confirmation_name, admin_id)`
    - Updates `purge_status = 'scheduled'`, `purge_at = func.now()`.
  - **Restore Validation Modification:**
    - Reject restore with `FolderPermanentlyDeletedException` (410) if `purge_status` is `purging` or `purged`.

## 5. Background Workers

### Celery Tasks (`backend/tasks/folders.py`)
- `cascade_move_subtree(source_id, workspace_id, old_path_prefix, new_path_prefix, depth_delta, actor_id)`
  - Streams batches of 200, updates `path` with `REPLACE`, updates `depth`.
  - Clears `cascade_status` to `NULL` upon completion.
  - Handles retries (up to 10), DLQ routing on failure.
- `hard_delete_folder_subtree(folder_id, workspace_id)`
  - Acquires Redis distributed lock.
  - Stores progress in a Redis sorted set checkpoint.
  - Executes deletions deepest-first: DB Document -> Qdrant -> S3 -> DB Folder.
  - Queue: Route to `folders.purge` queue.
- **Cron Worker** (`backend/services/folder/retention_worker.py`):
  - Runs every 6 hours via Celery Beat.
  - Finds root soft-deleted folders past their `purge_at`.
  - Dispatches `hard_delete_folder_subtree` tasks.

## 6. API Layer

### Endpoints (`backend/api/v1/routes/folders.py`)
- **Move:** `POST /workspaces/{workspace_id}/folders/{folder_id}/move`
  - Requires `FolderMoveRequest` (`target_parent_id`, `version`).
  - Returns `202 Accepted` with `FolderMoveResponse` (`cascade_pending`, `worker_task_id`).
  - RBAC: `[Role.ADMIN, Role.MEMBER]`.
- **Early Hard Delete:** `DELETE /workspaces/{workspace_id}/folders/{folder_id}/hard-delete`
  - Requires `FolderHardDeleteRequest` (`confirmation_name`, `reason`).
  - Returns `202 Accepted`.
  - RBAC: `[Role.ADMIN]`.
- **Purge Status:** `GET /workspaces/{workspace_id}/folders/{folder_id}/purge-status`
  - Returns retention metadata.
