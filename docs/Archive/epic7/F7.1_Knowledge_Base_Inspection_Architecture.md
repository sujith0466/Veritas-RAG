## 1. Executive Summary & Business Intent
Feature F7.1 provides a unified, enterprise-grade inspection platform and API suite for workspace administrators and data stewards to audit, inspect, and analyze their knowledge corpus. It delivers full transparency into document indexing status, chunk segmentations, vector dimensions, and Qdrant vector parity without exposing raw database or vector cluster credentials.

### 2.1 Key Functional Requirements
1. **Workspace Knowledge Overview (`GET /api/v1/workspaces/{workspace_id}/knowledge-base/overview`)**:
   - Total documents by status (`PENDING`, `PROCESSED`, `FAILED`, `ARCHIVED`).
   - Total document versions and cumulative storage bytes.
   - Aggregate chunk count and average tokens per chunk.
   - Total vectors indexed in Qdrant collection for the workspace namespace.
   - Qdrant parity flag (`is_vector_parity_synced`).
   - Breakdown by MIME type (`pdf`, `docx`, `txt`, `csv`, `md`).

2. **Paginated Document Knowledge Catalog (`GET /api/v1/workspaces/{workspace_id}/knowledge-base/documents`)**:
   - Filter by folder, status, MIME type, staleness, and metadata tags.
   - Sorting by date, word count, chunk count, and health impact.
   - Per-document indexing summary (version, chunk count, vector status, OCR engine used).

3. **Granular Chunk Inspector (`GET /api/v1/workspaces/{workspace_id}/knowledge-base/documents/{document_id}/chunks`)**:
   - Lists all text chunks belonging to the document's active version.
   - Chunk metadata: `chunk_index`, `token_count`, `char_length`, `qdrant_point_id`, `content_preview`, `has_embedding`, `bounding_box` / `page_number`.

4. **Vector Parity Validator (`GET /api/v1/workspaces/{workspace_id}/knowledge-base/vectors/validate`)**:
   - Verifies 1:1 parity between PostgreSQL document chunks and Qdrant points.
   - Identifies orphaned points or missing embeddings.

## 3. Data Contracts & Schemas

### 3.1 Knowledge Base Overview DTO
```python
class KnowledgeBaseOverviewDTO(BaseModel):
    workspace_id: UUID
    total_documents: int
    active_documents: int
```

## 4. Security & Tenant Isolation
- Strict Workspace Isolation: All database queries filter on `workspace_id` / `tenant_id`.
- RBAC Guard: Requires `WORKSPACE_VIEW` or `KNOWLEDGE_INSPECT` permissions.
- Zero Leakage: Content snippets sanitized and truncated to prevent sensitive credential exposure in inspection views.
