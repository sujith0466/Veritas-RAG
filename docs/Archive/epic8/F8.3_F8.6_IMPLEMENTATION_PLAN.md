# F8.3–F8.6 IMPLEMENTATION PLAN

## Goal Description
Implement Epic 8 Batch 2 (Features F8.3–F8.6) to standardize, harden, and optimize Server-Sent Events (SSE) streaming within RAGuard V2. This plan incorporates 15 mandatory enterprise improvements for robust recovery, structured errors, detailed observability, and precise timeout handling.

## Proposed Changes

### Phase 1: Pre-Requisite Bug Fixes
- **`backend/ai/wrapper/service.py`**: Add `import asyncio` to fix `NameError` during cancellation.
- **`backend/modules/chat/api/dependencies.py`**: Fix the `ChatOrchestrator` factory arguments to match `__init__`.
- **`backend/ai/interfaces/llm_provider.py`**: Update `LLMRequest` to include `tenant_id: str` and `workspace_id: str | None`.
- **`backend/ai/providers/v1_engine/provider.py`**: Update `generate` and `stream` methods to pass the actual `tenant_id` and `workspace_id` instead of dummy UUIDs.

### Phase 2: Feature Flags & Observability Setup
- **`backend/core/config.py` (or relevant feature flag module)**: 
  - Add feature flags: `ENABLE_SSE_RECOVERY`, `ENABLE_SSE_HEARTBEAT`, `ENABLE_TIMEOUT_EVENTS`, `ENABLE_PARTIAL_PERSISTENCE`.
- **`backend/observability/metrics/prometheus.py`**: 
  - Add metrics: `active_streams`, `replayed_chunks`, `redis_buffer_hits`, `redis_buffer_misses`, `average_stream_duration`, `average_chunks`, `average_ttft`, `cancellations`, `reconnects`, `timeout_counts`.

### Phase 3: F8.3 — SSE Stream Bridge & DTOs
- **`backend/api/v1/schemas/sse.py`**: Create `SSEMessageDTO`.
  - Reserved event types: `connected, heartbeat, progress, retrieval, reasoning, metadata, citations, reliability, warning, error, done`.
  - Support optional comment frames for heartbeat/keepalive.
  - Safe delimiter for `Last-Event-ID` (`:`). Example: `req-uuid:12`.
  - Structured Error payloads: `code`, `message`, `retry_after`, `correlation_id`, `recoverable`.

### Phase 4: F8.4 — SSE Recovery & Heartbeats
- **`backend/modules/chat/api/routes.py`**: Parse `Last-Event-ID` using `:` delimiter.
- **`backend/modules/chat/services/chat_orchestrator.py`**:
  - Redis buffer: Store structured JSON records (`correlation_id`, `chunk_index`, `timestamp`, `event_type`, `payload`).
  - Replay guarantee: strict ordering, no duplicates, no missing.
  - Failure to recover: If Redis replay buffer is expired/unavailable, do NOT silently regenerate. Return a structured `STREAM_EXPIRED` error event and require regeneration.
  - Idempotency: Maintain identical Correlation ID, Request ID, and Message ID across replay. Prevent duplicate DB messages.
  - Heartbeats: Send heartbeat events every 20-30 seconds during long streams.

### Phase 5: F8.5 — SSE Timeout Handling
- **`backend/ai/providers/v1_engine/client.py`**:
  - Implement independent timers: connection timeout, TTFT (time-to-first-token) timeout, read timeout, idle timeout, overall request timeout.
  - Ensure queue overflow blocks the producer (`Queue.put` is blocking).
  - Yield structured timeout error events on failure.

### Phase 6: F8.6 — Graceful Cancellation & Partial Persistence
- **`backend/modules/chat/services/chat_orchestrator.py`**:
  - On `asyncio.CancelledError`, persist partial message to `ChatRepository`.
  - Do NOT append `[Interrupted by user]`.
  - Persist interruption as metadata: `{"status": "PARTIAL", "is_interrupted": True, "completed": False}`.
- **`backend/ai/wrapper/service.py` & `v1_engine/client.py`**:
  - Rely natively on `asyncio.CancelledError` propagation. Ensure `await response.aclose()` executes. No unnecessary `sleep(0)`.
