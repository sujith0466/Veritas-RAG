# F8.7–F8.9 FINAL ENTERPRISE ARCHITECTURE REVIEW

## 1. Executive Summary
This document reviews the architectural designs for Epic 8 Batch 3, covering Reliability Score Extraction (F8.7), Citation Extraction (F8.8), and AI Policy Enforcement (F8.9). The designs strictly adhere to existing CQRS, Domain-Driven Design, and Event-Driven patterns.

## 2. Component Interaction & Data Flow
*   **Pre-Generation (F8.9):** The `AIPolicyMiddleware` sits inside `AIWrapperService`. It intercepts the request, applies tenant/workspace rules, redacts PII using the `DLPEngine`, and blocks jailbreaks. This guarantees that poisoned or non-compliant prompts never touch the Vector DB or the LLM.
*   **During Generation (F8.7 & F8.8):** `StreamingGroundedGenerationService` manages the LLM text deltas. It buffers context to identify sentence boundaries and citation markers. 
    *   Citation markers trigger `CitationExtractor`, yielding progressive `citations_delta`.
    *   Sentence boundaries trigger asynchronous `ReliabilityEngine` evaluation, yielding `reliability_score_update` deltas.
*   **Orchestration:** `ChatOrchestrator` maps these deltas to `SSEMessageDTO` events (`citation`, `reliability_score`) alongside standard `chunk` events.

## 4. Failure Scenarios & Retry Behavior
*   **Policy Violations:** Hard rejections (e.g., Blocked Topics) do not trigger retries. They immediately yield a `POLICY_VIOLATION` SSE error and terminate.
*   **Reliability Extraction Timeout:** Since reliability extraction runs concurrently via `asyncio.create_task`, if the scoring model fails or times out, the text generation is **not** interrupted. The score update is simply skipped for that sentence, and the final post-generation reliability pass acts as the ultimate fallback.
*   **PII Redaction Failure:** If `DLPEngine` becomes unavailable, the policy engine fails closed, blocking the request to prevent accidental data leakage.

## 5. Security & Multi-Tenancy Review
*   **Security:** `DLPEngine` guarantees PII never reaches third-party LLMs. `PromptGuard` sanitizes inputs before vector search, preventing poisoned context retrieval.
*   **Multi-Tenancy:** Policies are resolved hierarchically using Tenant IDs and Workspace IDs. A tenant can restrict topics across all workspaces, while a workspace can apply stricter token limits.

## 6. Performance & Scalability Review
*   **Performance:** Reliability scoring is asynchronous and decoupled from the critical LLM text-streaming path. The generation stream will not block waiting for reliability heuristics.
*   **Scalability:** Topic blocking utilizes lightweight LLM models (`use_lite_model=True` / `gemini-3.1-flash-lite`), preventing expensive large models from being tied up by malicious traffic.

## 7. Enterprise Recommendations & Risk Assessment
*   **Recommendation:** Limit the frequency of Reliability Score SSE events to every 2-3 sentences to prevent network flooding and React UI re-render thrashing.
*   **Risk:** PII redaction (masking) could alter the semantic meaning of the query, leading to degraded retrieval accuracy.
*   **Mitigation:** `DLPEngine` should use format-preserving or token-preserving redaction (e.g., `[REDACTED_SSN]`) rather than completely removing the text, providing context to the LLM without exposing the data.
