# F8.3 — SSE Stream Bridge Architecture

## 1. Executive Summary
Feature F8.3 standardizes and hardens the Server-Sent Events (SSE) streaming bridge between the V1 Internal AI Engine, the AI Wrapper Service, the Chat Orchestrator, and the Frontend Client. Currently, the system uses basic `StreamingResponse` generators yielding raw strings (`"data: {...}\n\n"`). This feature introduces a robust, standard-compliant SSE pipeline utilizing typed event models, ensuring all SSE fields (`id`, `event`, `data`, `retry`) are properly managed and propagated.

## 2. Feature Scope & Objectives
*   **Standardized SSE Formatting:** Ensure all streaming endpoints emit strictly compliant SSE payloads.
*   **Event Typing:** Introduce distinct event types (`event: chunk`, `event: citations`, `event: error`, `event: done`) rather than overloading the `data` payload.
*   **Message IDs:** Assign monotonically increasing or UUID-based IDs to every emitted event to support future recovery mechanisms (F8.4).
*   **Retry Directives:** Emit the `retry:` field to instruct clients on reconnection intervals.
*   **Backpressure & Memory Management:** Ensure the existing `asyncio.Queue` producer/consumer pattern in `V1EngineClient` operates efficiently without memory bloat during slow client consumption.

## 3. Existing Infrastructure Reuse
*   `backend/ai/providers/v1_engine/client.py`: The `V1EngineClient.stream()` method (maintains the `asyncio.Queue` backpressure pattern).
*   `backend/ai/wrapper/service.py`: `AIWrapperService.stream_request()` (maintains the orchestration lifecycle and event dispatching).
*   `backend/modules/chat/services/chat_orchestrator.py`: `ChatOrchestrator.stream_chat()` (maintains the adapter pattern).
*   `backend/modules/generation/schemas/generation_dto.py`: `StreamingGenerationChunkDTO` (will be extended or wrapped).

## 4. Architectural Design

### 4.1. SSE Message Standard DTO
We will introduce a strict `SSEMessageDTO` model to encapsulate SSE fields before serialization.

```python
# backend/api/v1/schemas/sse.py (New)
class SSEMessageDTO(BaseModel):
    id: str | None = None
    event: str | None = "message"
    data: str
    retry: int | None = None

    def to_sse_string(self) -> str:
        # Serializes into standard SSE format
        # id: {id}\n
        # event: {event}\n
        # data: {data}\n
        # retry: {retry}\n\n
```

### 4.2. ChatOrchestrator Enhancements
The `ChatOrchestrator.stream_chat()` generator will be updated to yield formatted SSE strings using the new DTO, rather than manual string interpolation.

*   **Current State:** `yield f"data: {chunk.model_dump_json()}\n\n"`
*   **Target State:**
    ```python
    sse_msg = SSEMessageDTO(
        id=f"{correlation_id}-{chunk.chunk_index}",
        event="chunk" if not chunk.is_final else "done",
        data=chunk.model_dump_json()
    )
    yield sse_msg.to_sse_string()
    ```

### 4.3. Event Type Definitions
To separate concerns, the bridge will emit specific events:
*   `event: connected` — Emitted immediately upon successful workspace/auth validation.
*   `event: chunk` — Standard text generation deltas.
*   `event: citations` — Emitted when citation evaluation completes.
*   `event: done` — Stream completion sentinel (replacing the internal `[DONE]` hack).
*   `event: error` — Application-level errors (e.g., rate limits, guardrail failures).

### 4.4. V1EngineClient Backpressure Optimization
The `V1EngineClient` currently uses `asyncio.Queue(maxsize=100)`. 
*   We will retain this producer/consumer separation to ensure we consume from the httpx network buffer quickly.
*   We will ensure the consumer properly handles `asyncio.CancelledError` if the downstream client (via FastAPI `StreamingResponse`) disconnects, triggering an immediate shutdown of the producer task.

## 5. Security & Isolation
*   **Tenant Isolation:** The SSE stream continues to inherit the strict workspace and tenant validations from `AIWrapperService._validate_workspace()`.
*   **Information Disclosure:** Internal stack traces or `httpx` exceptions will be caught and mapped to safe, sanitized `event: error` payloads.

## 6. Race Condition & Resource Leak Analysis
*   **Producer Task Leak:** The `V1EngineClient`'s `_producer()` task MUST be cancelled in the `finally` block of the consumer. The current implementation does this, but we will add strict unit tests to ensure `await producer_task` handles the `CancelledError` without leaking the httpx connection pool.
*   **Double Yield:** The bridge must guarantee that an `event: error` and `event: done` are mutually exclusive terminal events.

## 7. Observability
*   The `EventDispatcher` continues to emit `AI_WRAPPER_REQUEST_COMPLETED` and `AI_WRAPPER_REQUEST_FAILED`.
*   We will log the total number of chunks yielded and the stream duration to `QueryAnalyticsRecord`.

## 8. Enterprise Recommendations
*   Adopt `sse-starlette` `EventSourceResponse` in a future refactoring phase to replace the raw `StreamingResponse` for even greater standards compliance, though our `SSEMessageDTO` adapter ensures immediate compliance without adding new third-party dependencies during Epic 8.
