# F8.1 & F8.2 — Enterprise Implementation Plan

## 1. Dependency Analysis
The implementation relies entirely on the existing RAGuard V2 core infrastructure. No new third-party packages need to be installed.
*   **Vector DB**: `AsyncQdrantClient` singleton pattern will be reused for `NamespaceResolver`.
*   **HTTP Client**: `httpx.AsyncClient` (already in dependencies) will be used for `V1EngineClient` connection pooling.
*   **Events**: `backend.core.events.dispatcher.EventDispatcher` will be used for publishing all `ai_wrapper.*` events.
*   **Cache/Rate Limiting**: `redis.asyncio` (already in stack) will be used for rate limits and namespace binding cache.
*   **Circuit Breaker**: `CircuitBreakerEngine` from Epic 7 will be reused.
*   **Configuration**: `pydantic-settings` (already used) for `V1EngineSettings`.

## 2. Exact Implementation Order
1.  **Phase 1: Configuration & Infrastructure Primitives**
    *   Implement `V1EngineSettings`.
    *   Update `Settings` to include `v1_engine`.
    *   Implement `NamespaceResolver` and `RateLimiter` interfaces.
2.  **Phase 2: DTOs & Events**
    *   Create `AIWrapperRequest`, `AIWrapperResponse`, `AIWrapperStreamChunk`.
    *   Add new `EventType` enumerations for F8.1 and F8.2.
3.  **Phase 3: F8.2 - V1 Internal API Client**
    *   Implement `V1EngineClient` (mTLS, pooling, retries, circuit breaking, SSE parser).
    *   Implement `V1EngineProvider` conforming to `LLMProvider` ABC.
    *   Register `v1_engine` in `ProviderRegistry` and `LLMProviderManager`.
4.  **Phase 4: F8.1 - AI Wrapper Service**
    *   Implement `AIWrapperService` orchestrating the full 14-step lifecycle (validation, binding, context injection, prompt construction, retrieval, generation, events).
5.  **Phase 5: API & Adapter Refactor**
    *   Implement new API routes (`/api/v1/ai/stream`, etc.).
    *   Refactor `ChatOrchestrator.stream_chat` to delegate to `AIWrapperService`.

*   `AIWrapperRequest`: Includes `session_id`, `workspace_id`, `query`, `conversation_history`, `guardrail_config`.
*   `AIWrapperStreamChunk`: Extends `StreamingGenerationChunkDTO` with `namespace_used` and `wrapper_metadata`.
*   `V1EngineStreamChunk`: Maps incoming SSE events from V1.

## 5. Configuration Additions
Add `V1EngineSettings` with defaults as specified in Architecture Q1 (Option B):
```python
class V1EngineSettings(BaseSettings):
    base_url: str | None = None
    enabled: bool = False  # Dormant by default
    client_cert_path: str | None = None
    client_key_path: str | None = None
    ca_cert_path: str | None = None
    signing_key: str | None = None
    min_version: str = "1.0.0"
    max_connections: int = 50
    max_keepalive: int = 20
    connect_timeout: float = 5.0
    per_attempt_timeout: float = 10.0
    total_timeout: float = 30.0

```

## 6. Service Layer Implementation (AIWrapperService)
*   **Workspace Validation**: 6-step checks against DB and Redis (Rate limit: 60/min/tenant, 20/min/user configurable via settings).
*   **Context Injection**: Truncate conversation history to 20% of `max_answer_tokens` budget.
*   **Retry Loop**: Will perform full re-retrieval upon query rewrite (Q5 Option A decision).
*   **Resilience**: Enforce L1 (5s retrieval, 25s gen), L2 (35s wall clock), L3 (10s watchdog) timeouts using `asyncio.wait_for`.
*   **Event Publishing**: `ai_wrapper.*` events fired sequentially at appropriate milestones.

## 7. Provider Layer Implementation (V1EngineClient)
*   **Singleton Pool**: Utilize FastAPI `startup` lifecycle to initialize `httpx.AsyncClient` with `httpx.Limits`.
*   **mTLS Context**: `ssl.create_default_context(Purpose.SERVER_AUTH)` loading cert/key and enforcing TLS 1.3.
*   **Request Signing**: Implement HMAC-SHA256 signature logic over `"{method}\n{path}\n{timestamp}\n{sha256(body)}"`.
*   **Retry Engine**: Exponential backoff wrapping httpx requests mapping to domain errors.

## 8. AIWrapperService Integration
*   `AIWrapperService` will inject `RetrievalOrchestrator`, `StreamingGroundedGenerationService`, `ConfidenceEngine`, `RetryStateMachine`, `EventDispatcher`, `NamespaceResolver`, `RateLimiter`.

## 9. V1EngineClient Integration
*   Health background poller implemented on startup checking `/v1/health` and updating Redis `raguard:v1_engine:health_cache`.
*   Semantic version check at startup against `/v1/version`.

## 10. LLMProviderManager Integration
*   `LLMManagerSettings.priority_list` natively handles fallback. If `v1_engine` throws `CircuitOpenError` or `V1EngineUnavailableError` (or is disabled), the manager will smoothly cascade to `OpenRouter` -> `Gemini`.

## 11. API Layer
Create `backend/ai/api/routes.py`:
*   `POST /api/v1/ai/stream`: Maps to `stream_request()`
*   `POST /api/v1/ai/generate`: Maps to `generate_request()`
*   `GET /api/v1/ai/health`: Aggregates Redis cache for V1, Qdrant, Providers.
*   `GET /api/v1/ai/capabilities`: Returns active feature flags.
*   `DELETE /api/v1/ai/cache/namespace`: Force flush Redis binding.

## 12. Middleware / Dependency Updates
*   **No middleware changes**: `JWTAuthenticationMiddleware`, `CorrelationIDMiddleware`, etc., remain completely untouched.
*   `X-Tenant-ID` is verified exclusively via the JWT `sub`/claim (done downstream by `AIWrapperService`).

## 14. Observability Integration
*   **Metrics**: Inject `raguard_ai_wrapper_*` and `raguard_v1_engine_*` counters/histograms into `backend/observability/metrics.py`.
*   **Tracing**: Wrap stages in OpenTelemetry spans. Extract `request.headers.get("traceparent")` and propagate to V1 Engine.
*   **Logging**: `structlog` context binding for `tenant_id`, `correlation_id`. Mask queries via `sha256(query.encode()).hexdigest()`.

## 15. Security Implementation
*   Validate `tenant_id` string as `uuid.UUID` before injecting into headers for V1 Engine.
*   Re-use `PromptGuard.sanitize_and_format_evidence` in Wrapper prompt construction.
*   mTLS enforces internal network segmentation.

## 16. Testing Strategy
*(Note: Automated testing implementation is typically deferred, but the design is test-ready)*
*   Unit Test: `V1EngineClient` signature validation using mocked time.
*   Unit Test: `AIWrapperService` retry state machine transitions using a mocked `ConfidenceEngine` and `RetrievalOrchestrator`.

## 17. Validation Checklist
*   [ ] `V1EngineSettings` parses correctly.
*   [ ] `V1_ENGINE_ENABLED=False` cleanly bypasses V1 client init and routes to `OpenRouter`.
*   [ ] `ChatOrchestrator` correctly converts `ChatRequestDTO` to `AIWrapperRequest`.
*   [ ] Chat application functions identically via existing `/api/v1/chat/sessions/{id}/stream`.
*   [ ] `/api/v1/ai/stream` accepts requests and yields SSE.
*   [ ] Qdrant `raguard_knowledge_{tenant_id}` is pinged and cached.

## 18. Rollback Strategy
*   If `V1EngineClient` causes issues, we can revert by setting `V1_ENGINE_ENABLED=false` or removing `v1_engine` from the `priority_list` environment variable (Zero-downtime rollback).
*   If `AIWrapperService` causes issues, we can revert `ChatOrchestrator` via `git checkout`.

## 19. Performance Considerations
*   Namespace resolution cached in Redis (5ms lookup).
*   `V1EngineClient` HTTP/2 multiplexing avoids TCP handshakes.
*   `ChatRepository` fetches limited to `limit=5` by default to avoid slow queries.

## 20. Production Readiness Checklist
*   All error types properly caught and mapped to standard HTTP responses.
*   OOM protection via bounded SSE queues (max 100 items).
*   Timeouts enforced (35s max wall clock).
*   PII correctly scrubbed from app logs.
