# F8.6 — SSE Graceful Cancellation Architecture (Context Kill on Disconnect)

## 1. Executive Summary
Feature F8.6 ensures that when a client prematurely disconnects from an active SSE stream (e.g., closing the browser tab, navigating away), the backend immediately detects the disconnection, halts the LLM generation, releases network connections, and avoids wasting expensive AI inference resources.

## 2. Feature Scope & Objectives
*   **Disconnect Detection:** Detect HTTP client disconnections in real-time.
*   **Cancellation Propagation:** Ensure `asyncio.CancelledError` bubbles down the entire call stack.
*   **Resource Cleanup:** Close outbound HTTP connections to providers (V1 Engine, OpenRouter) immediately.
*   **Audit Logging:** Log the cancellation event accurately without triggering false "Failed" alerts.

## 3. Existing Infrastructure Reuse
*   `backend/ai/wrapper/service.py`: `stream_request()` exception handling block.
*   `backend/ai/providers/v1_engine/client.py`: `_producer()` task and consumer `finally` block.
*   `backend/modules/chat/services/chat_orchestrator.py`: Chat message persistence layer.

## 4. Architectural Design

### 4.1. Fast API & asyncio.CancelledError
FastAPI's `StreamingResponse` automatically raises an `asyncio.CancelledError` inside the generator if the client drops the TCP connection.

The primary architectural goal is to **unblock** and **propagate** this error, rather than swallowing it or blocking the event loop.

### 4.2. Propagation Chain
1.  **Client Disconnects** → Uvicorn detects closed socket.
2.  **StreamingResponse** → Raises `CancelledError` in `ChatOrchestrator.stream_chat()`.
3.  **ChatOrchestrator** → Allows error to bubble up, but ensures a `finally` block saves whatever partial message was generated to the `ChatRepository`.
4.  **AIWrapperService** → Catches `CancelledError`, dispatches `EventType.AI_WRAPPER_REQUEST_CANCELLED`, and re-raises.
5.  **LLMProviderManager** → Bubbles the cancellation.
6.  **V1EngineClient** → The consumer loop receives `CancelledError`.
    *   The `finally` block executes: `producer_task.cancel()`.
    *   The `_producer()` task catches `CancelledError` and explicitly calls `await response.aclose()` on the `httpx` stream to sever the connection to the V1 Engine.

### 4.3. ChatOrchestrator Partial Persistence
Currently, `ChatOrchestrator` saves the assistant's message *after* the stream completes.
If a `CancelledError` occurs, the generated text is lost.

**Update:**
```python
full_assistant_text = ""
try:
    async for chunk in self.ai_wrapper_service.stream_request(...):
        full_assistant_text += chunk.text_delta
        yield ...
except asyncio.CancelledError:
    logger.info("Client disconnected, persisting partial response.")
    raise
finally:
    if full_assistant_text:
        # Save partial response to ChatRepository
        await self.chat_repo.add_message(
            role="assistant", 
            message=full_assistant_text + " [Interrupted by user]"
        )
```

### 4.4. Request.is_disconnected() Polling
While `CancelledError` is raised on yield, long periods between yields (e.g., during the Retrieval phase which can take 500ms-1s) could block cancellation.
To mitigate this, we will interleave periodic `await request.is_disconnected()` checks during heavy asynchronous phases.

*   **Location:** Before retrieval, before generation, and between heavy iterations.
*   **Action:** If `True`, manually raise `asyncio.CancelledError`.

## 5. Security & Resource Management
*   **Connection Pool Leaks:** Failing to call `aclose()` on `httpx` streams leads to connection pool exhaustion. Strict unit testing must verify that `V1EngineClient.close()` is invoked upon cancellation.
*   **Token Waste:** Terminating the upstream request instructs providers like OpenRouter and V1 Engine to halt token generation, saving API costs.

## 6. Observability
*   Emitted event: `AI_WRAPPER_REQUEST_CANCELLED`.
*   Metrics: Increment a Prometheus counter `raguard_generation_cancelled_total` to track user abort rates.
