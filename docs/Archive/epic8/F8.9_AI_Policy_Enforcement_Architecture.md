# F8.9 AI Policy Enforcement Architecture

## 1. Overview
F8.9 introduces a strict enterprise policy middleware that executes **before** any request reaches the LLM. This middleware enforces organizational governance, including token limits, PII redaction, prompt injection blocking, and topic restrictions, with support for Workspace and Tenant-level overrides.

## 2. Component Architecture

### 2.1 `AIPolicyMiddleware`
We will introduce `AIPolicyMiddleware` directly into the `AIWrapperService.stream_request` orchestration pipeline (between Workspace Validation and Hybrid Retrieval). 

The middleware acts as a Chain of Responsibility utilizing existing security modules:
1.  **TokenLimitEvaluator:** Validates the query size and historical context against `max_answer_tokens` and Tenant token budgets.
2.  **PromptInjectionEvaluator:** Uses the existing `PromptGuard` to block jailbreak attempts before retrieval.
3.  **TopicRestrictionEvaluator:** Uses a fast, lightweight LLM (`use_lite_model=True`) to classify the query intent. If it matches a blocked topic (e.g., "financial advice", "competitor analysis"), it halts execution.
4.  **PIIRedactionEvaluator:** Utilizes the existing `DLPEngine.redact(prompt)`. It seamlessly mutates `AIWrapperRequest.query` to mask sensitive entities (e.g., replacing SSNs with `[REDACTED_SSN]`) before it is embedded for retrieval or sent to the LLM.

### 2.2 Hierarchical Policy Resolution
Policies are resolved in the following order of precedence:
1.  **System Defaults** (Hardcoded minimum safety floors)
2.  **Tenant Policy** (Stored in DB, cached in Redis)
3.  **Workspace Policy** (Stored in DB, cached in Redis)

### 2.3 Event Logging & Violations
*   If a query is safely redacted, the execution continues, but the `ComplianceAuditor` logs a `PII_REDACTED` event.
*   If a query violates a hard block (e.g., Prompt Injection, Blocked Topic), the middleware raises a `PolicyViolationError`.
*   The `ChatOrchestrator` catches `PolicyViolationError` and emits a structured `SSEMessageDTO.error(code="POLICY_VIOLATION", message="...")`. The HTTP connection is closed cleanly, and the attempt is logged in the `QueryAnalyticsRecord` with a `BLOCKED` status.

## 3. Data Flow
1. `AIWrapperService` receives `AIWrapperRequest`.
2. `AIWrapperService` delegates the request to `AIPolicyMiddleware.evaluate()`.
3. Middleware fetches active policies from Redis/DB.
4. `DLPEngine` scans for PII -> Mutates query if necessary.
5. `PromptGuard` checks for jailbreaks -> Raises if detected.
6. `TopicEvaluator` classifies intent -> Raises if blocked.
7. Mutated, safe `AIWrapperRequest` is returned to `AIWrapperService`.
8. Generation proceeds normally.
